# Tomba! beta prototype, 1998-02-03 ("TOMBI NTSC Preview Version")

Spanish twin: [BETA_980203_ES.md](BETA_980203_ES.md).

A CD-R labelled "TOMBI NTSC Preview Version", catalogued as "Tomba! (Beta prototype) (1998-02-03)". The disc and anything
extracted from it stay local, like `game/`. This page records findings only. Tool: `tools/beta980203.py` (load lists,
text dump, 8 bpp picture scan). Matching target: `--version beta980203` (see "Matching target").

**In short:** an English-localization build made two months after the JP retail build and seven weeks before the
USA one. Its code and data sit between JP and USA. It has an early English script, a "100 year old man" movie with
burned-in English subtitles, and an instrumental opening. **It has no cut Civilization data:** the four town
sections are already empty, and their text is already "···??".

## Where it sits: JP, beta, USA, PAL

**Layout.** It uses the JP layout: two-digit overlay names (`X00.BIN`..`X19.BIN`, copies in `AREAnn/`), `INFO*.BIN`,
`DSPSUB*.BIN`, `OPTSUB00.BIN`, and no `SYS/LD*` files. The load lists and the file table are inside the exe. There
is one language, so there are no `MFNT*`/`CFNT*` files: the text is WFM3 blocks (the PAL/USA format) embedded in the
area GAMs. It has the western pieces too: `SYSTEM/GOVER.BIN` + `G000000.000` (the Game Over overlay and picture; USA
has the same names, PAL has `G0OVER..G8OVER` + `A09300`). The JP exe string `" GAME OVER "` is gone (`" Wonderful "`
sits there instead). `AREAnn/A000.GAM` is 178 bytes, the USA size (JP: 316).

**Files by content** (1084 files, GAM files compared as stored):

| Same bytes as | Files |
|---|---|
| JP, USA and PAL | 233 |
| USA and PAL, not JP | 266 |
| JP only | 126 |

The 445 unmatched files are the code (`SLPS_011.44`, every `Xnn.BIN`, `INFO*.BIN`, `DSPSUB*.BIN`), every GAM that
holds text or HUD words, the area `CLUTnn` (two shared HUD rows differ, below), level data whose pointers moved, and
the sound banks.

**Code.** `tools/xmatch.py` (PAL functions found by masked match):

| Program | JP retail | Beta | USA |
|---|---|---|---|
| boot exe | 976 functions, 39.9 % of bytes | **1087, 44.4 %** | 1192, 61.4 % |
| `SYSTEM/X00.BIN` | 346, 44.9 % | **431, 61.1 %** | 524, 90.5 % |

The overlay base is 0x800EDAA8 (JP 0x800E9AF8), from jal targets on X00 prologues. Every `Xnn.BIN` starts with the
first 0x2BC48 bytes of `X00.BIN` (JP: 0x2B680).

## Civilization (AREA11/16/17/18): nothing new

The checks were the same as for the USA disc (docs/CIVILIZATION.md, "USA disc").

- **Section-0 load lists are empty.** The section counts are a u16 table at 0x800786F0, and the list pointers are at
  0x800A1478 (20 area lists, then each area's section lists in order). `tools/beta980203.py lists` gives:
  AREA11 `[0, 21, 12, 0, 0]`, AREA16 `[0, 0, 0, 12, 13, 15, 13]`, AREA17 `[0, 10, 13, 11, 11, 13, 0, 0, 0, 0, 0]`,
  AREA18 `[0, 18, 14]` records per section. These are the USA counts, except AREA18 s1/s2, which still load their own
  sound bank (0x93 `SND0181/0182.WVD`, as in JP) and a 0xB0 block.
- **No 0x8E / 0x8F / 0x3B..0x3E block that retail lacks.** Every load-list block was hashed (SYS and area lists) and
  compared with every PAL load-list block, every USA load-list block, and every whole file on PAL, USA and JP. The new
  blocks are kinds 0x10 (pages and CLUTs), 0x30/0x31/0x34/0x39 (sprite tables), 0x50/0x51 (models), 0x60 (WPP),
  0x70/0x71, 0x80..0x89 (placement), 0x93/0x94 (sound), 0xB0, 0xC0/0xC1 (WSS), 0xD0/0xD1 (text and fonts) and 0xF0
  (code). In the town areas they are the side-scrolling sections' sprite tables, placements, CLUTs and code.
  0x8E/0x8F appear only in the working top-down areas (AREA02, 05, 08, 19), and their blocks are byte-identical to retail.
- **8 bpp pictures:** only the seven known top-down maps (AREA02 `D005`, AREA05 `D003`/`D203`, AREA08 `D002`/`D202`,
  AREA19 `D005`/`D206`). Their pixels are identical to retail.
- **Scenery CLUTs:** `tools/clut_catalog.py` (the beta is now a default disc, `beta=/dev/shm/beta/fs`) finds 1991
  distinct 16-colour rows on the beta, 57 of them only here. Those 57 are HUD/system rows: the 39-row run in `X03.BIN`,
  nine rows in each AREA10 CLUT, a few in AREA00..04/12, and two rows (row 9 and row 14 at column 192) shared by every
  area CLUT, AREA11/16/17/18 included. No town-specific row is new.
- **Female Stonetown Resident palette** (TCRF sprite, `clut_catalog.py test --sprite`): best 24.1 on every disc,
  the same shared row as before (AREA00/CLUT06 r7). The beta adds nothing closer, so the AREA16/CLUT07 rows 48 / 54
  guess stands.
- **Text:** the beta has the same 351 "···??" placeholder slots as USA. Each of the 51 WFM3 blocks has the same
  number of dialogues as its USA twin, and no slot has text where USA has the placeholder. The cut towns' lines
  (MFNT110 #249-#265, MFNT160/170 #213-#218, #257-#268, #270-#289, MFNT180 k2) were blanked before this build, so
  the only text for them is still the Japanese.
- Same art: AREA18 `B102` (the Iron Men / big men page) differs from JP by a few retouched pixels. AREA11/16
  `A001` and AREA17 `A002` differ from USA by a few effect sprites (a glow orb and sparkles).

## Other changed content

1. **Early English script.** About half the dialogue slots differ from USA: 5270 of 10581, ignoring box sizes and
   line breaks, with 1594 distinct changes. Examples (beta → USA):
   - "Potencial MAX !" / "Not enough Potencials" → "Experience MAX!" / "Not enough Experience!"
   - "Treasured Fish" → "Sacred Fish"; "Grandpa's Keepsake" → "Grandpa's Bracelet"; "Energy Bar" → "Fuel Bar"
   - "100,000,000 Year Old Bell/Key" → "Million Year Old ..."; "Bonsugi" → "Bonsugee"; "Invisible Mirror" → "Dirty Mirror"
   - "Giant Bird" (39 times) → "Phoenix"
   - the untranslated Japanese name "KOMABUTA" (4 lines, e.g. "I've been meddling with the KOMABUTA") → "Evil Pig"
   - the dwarf counter counts up: "One dwarf rescued!" … "Six dwarfs rescued!" → "Six dwarves remaining!" …
     "One dwarf remaining!"
   - event titles: "Camp Memories" (USA "Something's Cookin'?"), "The Legendary Leaf Butterfly", "The Lost Dwarf",
     "Fire's Worst Enemy", "Just Wanna Be Myself Again", "The Thief's Wish", "The Witch Who Caught A Cold",
     "Dream? Illusion? Find the Treasures", "Where are you, my son...", "A Real Magic Pig", **"The Million Tower"**
     (USA "The Flower Tower").

   All 2068 voice codes are `{VOICE 11 0}`: no per-character text blips yet (USA uses 6, 13, 15, 12, ...). The
   dummy event title "!!!DUMMYCUBE!!!" (event #1) is in both.
2. **`MOVIE/100US.STR`** (467 frames, 320x224, file dated 1997-10-26): the 100 year old man's intro. It is the JP
   `100JP.STR` cut with **English subtitles burned into the picture**: "This was once a beautiful, peaceful land...
   until 7 Evil Pigs came.", "They suddenly appeared and used their powers to change this land into an ugly world...",
   "For some reason, the Evil Pigs seem to be collecting gold.", "I bet your Grandpa's bracelet that was stolen by the
   KOMABUTA was made out of gold, too.", "If you find them, I'm sure you'll be able to find your bracelet as well."
   USA `100US.STR` is a different, longer encode with no subtitles in the picture. The video sectors differ from JP
   in 3193 of 3588; all 512 audio sectors differ.
3. **`MOVIE/OP_INST.STR`** (1414 frames, dated 1997-10-25): the JP `OP_UTA.STR` opening with **identical video**
   (all 10850 video sectors match) and different audio (all 1550 audio sectors differ). The name says why: an
   instrumental track in place of the Japanese song. USA's `OP_INST.STR` is a different, longer encode.
4. The other movies have JP sizes (e.g. `ENDING.STR`, `BOY.STR`, `SORA1/2`), where USA has longer re-encodes and
   `END_US.STR`.
5. **Small new files:** `SYSTEM/A000132.000` (320 bytes) and `A000133.000` (32 bytes), palettes loaded by SYS list 2
   next to `A000131` (= PAL `A10301`); `AREA10/SND0101.WVD` and `SND0101X.WVD` (sound banks with no byte-identical
   twin on retail).

## Debug features

The exe has the same debug strings as JP retail (`AREA SELECT = %02d`, `SECTION SELECT = %02d`, `flag= %01d`,
`hit pos x= %04d` ...; USA keeps the first two). No new debug strings were found: the only exe strings that are on
neither JP nor USA are the date stamp and `" Wonderful "`. How to open the area select was not checked.

## Matching target

`--version beta980203` (alias `beta`, macro `VERSION_BETA_980203`), `config/beta980203/`: the boot exe
(text 0x80016070..0x8007555C) and `SYSTEM/X00.BIN` (vram 0x800EDAA8). Symbols come from
`tools/xmatch.py ... --csv build/beta980203/xmatch.csv` + `tools/jpdemo_syms.py ... --version beta980203`. The
local game dir is `game_beta980203/` (`SLPS_011.44`, `SYSTEM/X00.BIN`; git-ignored). A first
`tools/build_report.py --version beta980203` gives 56.5 % of code (1372 of 1915 functions) from the shared tree with
no beta branches. CI job `report-beta980203` reads the secret `GAME_FILES_URL_BETA980203` (raw image or a zip with
the two files), checks both sha1, uploads `BETA_980203_report`, and is skipped when the secret is missing.

## Functions vs PAL (2026-10-30)

Tool: `tools/fn_vs_pal.py` (new). After `tools/xmatch.py` has paired every PAL function it can find by masked hash,
the script cuts the gaps between the hits at stack-frame prologues, scores each piece against every PAL function
(Jaccard of masked 3-word shingles, 0..100) and looks for an exact masked twin in JP retail.

```
python3 -I tools/xmatch.py game_beta980203/SLPS_011.44 game_beta980203/SYSTEM/X00.BIN --csv m.csv
python3 -I tools/fn_vs_pal.py game_beta980203/SLPS_011.44 m.csv --vram 0x80010000 --text 0x80016070 0x8007555C --also game_jp/SLPS_011.44
python3 -I tools/fn_vs_pal.py game_beta980203/SYSTEM/X00.BIN m.csv --vram 0x800EDAA8 --min 64 --also game_jp/SYSTEM/X00.BIN
```

Only the boot exe and `X00.BIN` are extracted locally; `X01..X19`, `DSPSUB*`, `INFO*` were not compared. The `PAL name`
that the script prints for a low score is only the nearest by shingles and is often wrong (e.g. it offers
`updateSceneSequence`, a PAL overlay function, for a boot-exe function): treat a score under 30 as "no counterpart".

| Program | Masked twins in PAL | Gap pieces >= 48/64 B | with sim >= 60 (a revised PAL function) | JP exact twin | no PAL, no JP |
|---|---|---|---|---|---|
| boot exe | 1087 | 165 (125 KB) | 67 | 79 | 86 |
| `X00.BIN` | 428 | 91 (130 KB) | 71 | 33 | 58 |

Reading: the beta is a revision of the JP code that PAL then rewrote again. Most of the "no counterpart" bytes are
the same PAL function in an earlier form (weapon swings 87-91 %, player states 70-98 %, sprite drawers 64-93 %),
not cut features. Three of the biggest `X00` pieces are not code at all: 0x800EDAA8 (7336 B, the area-handler
pointer table), 0x801182B4 (7408 B) and 0x8013BB60 (15352 B, pointer tables to handlers): no `jr ra`, sim 0.

### Real no-counterpart code (boot exe, sim < 30, ranked)

1. **Collision-probe debug object, 0x800311E4 (972 B).** *Verified.* It calls `drawDebugText` 6 times and `sprintf` 6
   times with the strings `flag= %01d`, `hit pos x= %04d`, `hit pos y= %04d`, `no hit`, `pos x= %04d`,
   `pos y= %04d`, `dir = %01d` (0x80010614..0x8001066C), uses `probeCollisionAtDepthC` and `AnimLoadDuration`, and
   frees itself with `ObjFree`. It is the same object as PAL `updatePoolType31Object` (0x8002E83C, 624 B), but PAL
   has none of the seven strings (they are absent from MAIN0.EXE): the debug read-out was stripped. The docs
   knew the strings; this ties them to the object. Not checked: what spawns it (an emulator run would show the
   overlay of hit pos / dir on screen).
2. **Boot task, 0x80018E3C (1348 B; PAL `bootStartupTask` 0x478 B).** *Verified.* It prints the build stamp
   `98/2/3` `4:12` and `" Wonderful "` (0x80010000..0x8001003C) with `drawDebugText` x5, calls `loadButtonConfig`,
   `memset` x2 and `SetDispMask` x3. PAL dropped the on-screen stamp. Guess: the boot screen showed the build date
   to testers.
3. **Glyph scene object, 0x8002F084 (2444 B).** *Structure verified, purpose guessed.* A state machine (byte +4, sub-state
   +5, a 60-frame timer at +34): `loadMessageGlyph`, `freeMessageGlyph` x5, `GetClut(336,..)`, `openMenuScreen(4)`,
   sound calls with ids 10, 11, 27 and 28 (through 0x8001F72C), then `getBaseMatrix`/`MulMatrix0`/`ApplyRotMatrix`/
   `SetRotMatrix`/`SetTransMatrix`: it draws a rotating 3D-matrix sprite over message text. PAL's callers of
   `loadMessageGlyph` are only in the DSPSUB overlays (`subScreenMessageStep`, which has no matrix code), so the PAL
   equivalent either moved to an overlay not checked here or was cut. Guess: a result or reward screen (item-get /
   game-over style). DSPSUB of the beta is needed to settle it.
4. **Area/section event object, 0x8005786C (1496 B).** *Structure verified, purpose guessed.* Not PAL
   `updateMightyFishFood` (that is an overlay function). It picks an animation table and sprite id from the area
   (u16 at 0x800A2440, a 20-entry jump table) and the section (0x800A2442, per-area ranges 0..7), calls
   `GetClut(..,505)`, then runs `eventTakePlayerControlA`/`eventCarryPlayerB` or `C`/`D` depending on the flag byte
   0x800A2AD9. So it is the dispatcher of the "event takes the player" objects, with per-area animation choice.
   The same logic exists in PAL under another layout (the `eventTakePlayerControl*` family is in PAL), so this is
   probably an earlier layout, not cut content.
5. **0x8001DB50 (1616 B).** Calls only `allocObjectLayer8` and reads many fields at 0x800B00xx; sits among the
   pause/inventory handlers (0x8001B5DC `inventoryScreenHandler`, 0x8001D058 `updatePauseMenu`). Purpose not determined.
6. Smaller: 0x80068590/0x80068290 (pad receive, PsyQ libpad of another version), 0x8001F678/F72C/F7FC (sound voice
   allocation, also in JP), 0x80059DE4 (320 B, no calls, no data refs: a leaf, also in JP). The ones with a JP twin
   but no PAL twin (`queueLoadList` 0x800214F4, `pushOutOfWallSegments` 0x80043C20, `probeFloorSegmentBelow`
   0x80042C48, `moviePlayerTask`) are JP code that PAL rewrote, so JP-era designs, not zombie code.

### `X00.BIN`

Nothing of size is without a PAL cousin. Lowest scores (all revised versions of PAL functions): `playerUpdateSpeedFromPad`
0x80113048 (29), `playerAirAccelerateX` 0x80112924 (34), `weaponTrailOrbitStep` 0x800F15DC (22),
`updateWeaponTrailObject` 0x800F184C (27) and `...Alt` 0x800F17EC (22), `drawObjectProjectedSpriteB` 0x8012762C
(19, has a JP twin), `charlesTalkCheck` 0x8013ABC4 (43). No new strings: every ASCII string of 6+ characters in
`X00.BIN` is also in PAL MAIN0.EXE.

### Strings

Every 6+ character string of the exe and `X00.BIN` that is not in PAL MAIN0.EXE: the build stamp, `" Wonderful "`
and the seven probe strings above. Nothing else.

### Load lists, areas, text

Nothing new beyond the sections above: the load-list and 8 bpp checks of "Civilization: nothing new" cover the
